# 澄音 Windows 桌面版 Implementation Plan

用户明确要求双击打开独立窗口，沿用已确认的播放器界面与全部现有功能。本次是交付方式变更，不重新设计界面。

**Goal:** 交付直接打开窗口的 Windows 应用和桌面入口，内置运行环境，无需 Node.js 或浏览器操作。

**Architecture:** 使用本机已缓存的 Electron 42.4.1，打包现有生产界面、音乐服务与生产依赖。使用固定的应用协议保持曲库来源稳定，后台 API 仅监听回环随机端口；退出时关闭服务。窗口关闭后数据保存到用户应用数据目录。

**Files:** desktop/main.cjs、desktop/protocol.mjs、desktop/service.mjs、desktop/build.mjs、desktop/README.md、tests/desktop-protocol.test.mjs、tests/desktop.e2e.mjs，以及 desktop-app/ 交付目录。保留原有网页版入口与其他项目文件。

## Validation

主页面在独立窗口显示；不出现浏览器或命令窗口；测试中拒绝外部导航与新窗口；曲库和主题在重新打开后恢复；重复启动聚焦原窗口；不需要系统 Node 参与运行。


## 完成记录

- Windows 应用位于 desktop-app/澄音播放器.exe，根目录 ClearPlayer.exe 是带图标的原生 GUI 入口。已创建桌面“澄音音乐”快捷方式，旧 start-player.cmd 也优先打开桌面版。
- 打包 EXE 实测通过：独立可见窗口、渲染隔离、内置 API、文件导入与真实播放、歌词定位、播放中切换外观、收藏、关闭窗口退出和重开恢复。原生入口重复启动保持单窗口。
- 固定 clear://player 来源保证随机后台端口不会改变 IndexedDB 来源。下载、曲库、主题和窗口设置使用用户应用数据目录；浏览器数据不自动迁移，已在说明中告知首次重新导入。
- 协议与批处理兼容性测试 3/3，通过现有 npm test 53/53，生产构建通过。独立静态复核未发现重要问题。
- QA 使用隔离测试数据目录，不向用户曲库添加测试音频。已打开实际桌面窗口供用户直接使用。
- 未改变在线提供方实现、未删除现有 EXE、未发布网站或设置开机自启。当前目录无 Git，不创建提交。
